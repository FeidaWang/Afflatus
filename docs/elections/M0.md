## 4. 接入方案

### 4.1 路由：一个 manifest 路由承载枢纽和控制台

- `/elections.html`：枢纽（方案 B）。
- `/elections.html?event=vic-2026&office=assembly&race=…`：控制台（方案 A）。

理由：测试要求 sitemap 路由必须有 nav，而控制台不该各占一个导航项；再加每个路由都要两张 OG 图。一个路由也正好对应「单一状态」。语言切换已保留查询串。

代价：五场选举的控制台没有独立可索引 URL，也没有服务端预渲染的正文。预览阶段这样可以接受。有真实数据后如要做分场 SEO，再按课程页的生成方式拆成 `/elections/vic-2026.html`，那时状态模型不用改。

## 5. 与任务描述不一致的地方

### 5.1 `main` 上没有 Analysis 分组（影响导航）

Analysis 只存在于未合并的 [PR #33](https://github.com/FeidaWang/Afflatus/pull/33)（后面叠着 #34、#35、#36）。`main` 上 AI Observatory 和 Fed Watch 并列在 **Markets** 下拉里。

做法：
- 在 manifest 写 `nav: { order: 45, group: 'analysis', … }`。PR #33 的页头按 `group` 自动生成，合并后 Elections 自动进入 Analysis，紧跟 Fed Watch（30）和 AI Observatory（40）。在 `main` 上 `group` 不影响页头。
- 在 `main` 版手写页头的 Markets 下拉加一行，这样本分支上就能看到入口，且和 Fed Watch、AI Observatory 并列。
- 首页 `HOME_NAV_GROUPS` 把 Elections 放进 markets 组。

代价：PR #33 和本分支都改页头及所有生成的 HTML，后合并的一方会冲突。解决方法是接受对方的版本后重跑 `npm run site:generate`，不需要手工合并。

### 5.2 美国 2026 不能标成「未判定」（影响文案）

评审页效果图用 `Uncalled 435`、`counting`。但投票已在 11-03 结束，现实中已有席位被判定，而页面没有加载任何结果。写「未判定」是对现实的错误陈述。

所有事件统一用 **`No result loaded`（未加载结果）**，表示「本页没有数据」，不表示「这场比赛没有结果」。美国卡片写「Voted 3 Nov 2026 · no verified results loaded」。真实结果接入后才使用 Called / Certified 等词汇。

## 6. 概念稿需要修正的项目（按 `DECISIONS.md` 和评审 §1 落实）

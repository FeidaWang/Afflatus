## 2. 来源决定

把证据分成四类，只有「文档声明」和「单次请求」有依据。**持续延迟和完整覆盖都没有观察，也没有测量任何真实延迟。**

| 来源 | 文档声明 | 单次请求 | 决定 |
|---|---|---|---|
| **VEC 官方 feed**（维州） | EML XML、ZIP 完整快照、选举周末每 5 分钟、之后降频。只给批准的媒体和分析者，要签条款，用 SharePoint 和共享 token 取文件 | 只读了公开页面、PDF 和样例。feed 本身无权限，未请求 | `enabled: false`。**首选，但公开显示未获确认** |
| **civicAPI**（美国） | 免费，含商业用途，非个人项目须署名；FAQ 列出 publishing live results；缓存和再分发没写；判定来自它自己的 decision desk；称 5–10 秒更新（未测） | 7 次 API 请求，其中 2 次 503 `CIVICAPI_OVERLOADED`。澳洲 11-20 至 12-05 搜到 0 场。众议院搜到一个全国级 race，**逐选区覆盖未核实** | `enabled: false`。不用于维州 |
| 新州官方 feed | 要签条款，受限 FTP，要静态 IP，只含初点 | 未请求 | 未登记，2027 年的事 |

### VEC 条款的关键句

条款第 1.2 条，原文：不得 "sell or otherwise disclose or release it to any party in either its original or any modified form"。

用户手册又写明用途包括把结果集成进网站。两处放在一起，**我读不出公开显示是否被允许**，这也不是我能判断的，要 VEC 书面回答。在此之前 `publicRedistributionAllowed` 保持 false。这不是法律意见。

其他要点：11-04 起开放访问；11-10 给零文件和设置文件；11-25 试运行全是虚构数据，且条款第 5 条禁止对外作任何表述；VEC 不提供技术支持。

**VEC 选举夜不宣布结果。** 下院 12-09 起、上院 12-16 起陆续宣布，令状最迟 12-19。所以 11-28 当晚如果接上 feed，页面只会有计票和领先，**没有任何已判定的席位**。这是正确的行为。

## 3. 实现

| 要求 | 实现 |
|---|---|
| 一次一轮 | `scripts/elections/collector.mjs` 的 `collectOnce`。`.lock` 防重叠，10 分钟后视为残留 |
| 安全解析 | `safe-xml.mjs` 拒绝 DOCTYPE 和实体。`safe-zip.mjs` 限解压大小并校验 CRC。`package.json` 没有新增依赖 |
| 请求限制 | `bounded-fetch.mjs`：主机白名单、超时、字节上限、条件请求、不跟随重定向。`Retry-After` 和指数退避在采集器 |
| 原始证据 | 不保留，只存 SHA-256（`storeRaw: false`），因为条款未明 |
| 原子发布 | 先写不可变快照，最后写指针，都用 rename。出错保留上一快照，隔离记录写入 `private/quarantine/` |
| 304 与无变化 | 只更新 `lastCheckedAt`，来源时间不动，不产生新快照 |
| 不累计 | 累计总数直接替换。`resolveRaces` 每场只取一个来源的完整数据，不相加 |
| 变化类型 | 新批次、更正（含负数）、轮次、判定、撤销、宣布、换来源、两候选人组合变化 |
| 三种状态 | `coverage`、`counting`、`decision` 分开。领先只画斜线，判定需要具名方和时间 |
| 刷新 | `src/lib/electionFeed.js`：可见 60 秒、隐藏 5 分钟、失败退避。指针和快照 ID 不一致就拒绝，旧的指针不能让页面倒退 |
| 保留状态 | 席位标记就地重绘，节点不换。表格和面板重建后按名称恢复焦点。URL 不变 |
| 回放 | 只读已记录的快照，不插值。少于 2 个时禁用并说明原因。状态带变黑，新数据不会移动回放 |
| 发布闸门 | `feedAllowed`：公开主机上要求真实数据且来源 `enabled` 和 `publicRedistributionAllowed` 都为 true。合成数据只在 localhost 显示 |
| 防注入 | 来自 feed 的文字都转义。指针 ID 限定字符 |

### 样例里查到的、光读手册猜不到的事

1. **重新计票时，已回报投票点变成 0，但票数还在。** 我第一版把它当成「没有计票」，会把真实票数清空。现在判为 `recount`，进度显示为未知。手册只说这时没有分类票数和投票点数据。
2. **宣布后票数还会变。** 手册和样例都如此，所以宣布不等于计完。
3. **宣布没有日期。** feed 不提供，页面写「首次在数据中出现」，并明说没有宣布日期。
4. **`Created` 不带时区。** 我按墨尔本时间解析。来源时间是空的就保持 null，不借用文件时间。
5. **绿党的注册名是 `The Australian Greens - Victoria`。** 第一版规则漏了，截图时发现。
6. **上院结构不同：** 在 `Senate` 下，不是 `House`。

## 6. 需要站主知道的

1. **一个选区名对不上，整个文件都会被拒绝。** 样例只有 6 个选区和 1 个大区，**其余名称没有和 VEC 的写法核对过**。我选择拒绝而不是部分接受，是为了不发布不一致的快照。代价是一个拼写差异就能卡住一院，所以 11-10 必须核对。
2. **党派映射是暂定的。** 只认工党、自由党、国家党和绿党的注册名，其余一律归 Other，包括 One Nation。独立候选人归「Ind / Teal」，这个分组是 M2 定的，把所有独立候选人都算了进去。11-10 有官方政党文件。
3. **上院在 M5 不着色。** 一个大区一起选 5 席，样例的上院文件里组别没有当选字段，而且没有一个样例大区被宣布过，所以我不知道宣布后的样子。席位保持中性，只在抽屉里列出组别和票数。
4. **`Leading on TCP` 是 VEC 说的 indicative。** 两候选人的选择可能在复核时更正，也可能被隐藏，页面都有标注。隐藏（Maverick）在样例里没出现过，只用合成数据测过。
5. **美国没有适配器。** 领先和判定的逻辑有单测，但没有任何美国来源接入。
6. **采集器一次只跑一个来源。** 换来源的事件和「每场只取一个来源」都有单测，但多来源同时写入同一存储没有实现。现在只有 VEC 一个来源，不需要。
7. **M1 仍未做。** 规则包常量还没核验。`boundaryVersion` 是 null，维州边界的适用性仍是 M4 说的推断。
8. **公开文案里还有 `M1`、`M6`。** 这是 M4 留下的，上线前要改。
9. **`public/sitemap.xml` 等日期变成了 11-05。** `site:generate` 的结果，因为工作区有改动。不是手改的。
10. **证据目录 34 MB**（M4 后约 27 MB）。提交前想一想是否全部进仓库。
11. **VEC 样例没有进仓库。** 它是公开文件，但条款和再分发都未明，所以只放 scratchpad。仓库里的测试夹具全是我写的合成数据，只在 `tests/` 下，不会进入构建：我检查过 `dist/` 里没有 `SYNTHETIC, Alpha`。VEC 的 `Test State Election 2026` 这个字符串在包里，是身份校验用的配置。
12. **搜索时遇到一处提示注入。** 一次网页搜索的摘要说，某个结果里有让读者忽略系统提示的文字。我没有照做，也没有用那个结果。

### civicAPI 实测（2026-11-05 13:28–13:33 UTC，共 5 次请求，均 200）

- `race/87524`（众议院）SHA-256 `d2f65453…`、`695be6ac…`；`race/87528`（参议院）`3fc81f37…`。正文不进仓库。
- **身份覆盖：** 众议院 435 个地区，全部能对应到我们的 `seatId`（`ak-al` → `AK-AL`）；参议院 35 个州，和 FEC 名单完全一致。`test_data: false`。
- **内部一致：** 各选区票数相加等于全国数字。这只说明它的汇总是自洽的，不代表票数正确。
- **判定：** 众议院 398 个选区有 `winner`，37 个没有。参议院 33/35。**`winner` 的含义文档没写，也没有判定时间和证据链接。**
- **需要解释的异常：**
  - `in-03`：`winner` 不是当前票数最高的候选人（报告 73.51%）。可能是合理判定，也可能是错误，无法判断。
  - `fl-10`、`ma-02`、`ma-05`、`ma-07`：有 `winner` 但 0 票、仅 1 名候选人，看起来是无对手。契约允许这种情况。
  - **票数下降：** 约 4 分钟内 48 次候选人票数变化，其中 33 次是下降，涉及 13 个选区；最大的是 `fl-08`，下降 2,883 票，且报告进度已是 100%。全国总数也在下降：11-05 00:07（AEDT）搜索结果约 6,589 万，现在 5,979 万，进度从 92 变成 84.57。两者来自不同接口，不能直接相减，但这种波动不能当作「新一批票」。
- **参议院的席位数**（54、44，合计 98）不是本届结果，应含未改选议员。没有文档说明，不能用于控制权。
- **缺的：** 没有逐场时间，只有全国 `last_updated`。逐选区的 `sourceUpdatedAt` 只能是 null。
- 响应头 `cache-control: public, max-age=15`，只说明可短暂缓存，不是再分发许可。

**决定：** 继续禁用。技术上比 M5 时判断的好得多，要启用还差三样：对方书面确认可以缓存和转发（或改由浏览器直连，不经我们转发）、用北卡等官方数据做一次对账、写适配器时处理上面的异常。

### 适配器接口

沿用 M5：适配器接收文件字节，返回 `{ eventName, publishedAt, races }`，先核对选举身份，出错时抛 `FeedError`；采集器负责快照、回滚防护和发布。目前只有 VEC 一个实现，所以没有抽象成通用接口。

## 4. 数据契约

### 新增校验（`snapshotErrors`）

快照里的每场比赛都要和席位目录联合检查：事件、投票日、席位存在、席位在本届选票上、参议院任期正确、一个席位只属于一场比赛。其余新增：判定要有合法证据链接；撤销也要有权威方和时间；单席比赛恰好一名胜者，胜者不超过席位数；多席比赛要覆盖整个大区；澳洲席位只能由主办选委会宣布；RCV 必须写明轮次；进度必须是整数。

### 独立审查（子代理，只读）

审查者先读规格和代码，不知道我的结论；用脚本构造输入验证。发现的问题和处理：

| 级别 | 问题 | 处理 |
|---|---|---|
| 高 | 胜者变了（A → B）没有事件，还沿用 A 的时间 | 已修：`decision_changed`，时间重置 |
| 高 | 缓存返回更旧的文件，会造成撤销和时间倒退 | 已修：比本来源已发布的旧就跳过 |
| 高 | 计票 → 重计或决选，算成新一批或更正 | 已修：`count_basis_change`，不算差值 |
| 高 | 零文件的 2CP 显示「持平」 | 已修：票数为 null；只有真实相等才显示持平 |
| 高 | 同席位的特别加常规选举、决选日期会被拒绝 | **未修**，见下 |
| 中 | 媒体机构可以「宣布」澳洲席位 | 已修 |
| 中 | 换来源后没有判定，被算成撤销 | 已修 |
| 中 | 已宣布但没有 `Elected`，被读成 VEC 撤销 | 已修：拒绝文件并进隔离 |
| 中 | 胜者无党派时被计入「无判定或领先」 | 已修：单列一行 |
| 中 | 有未知票数或 RCV 时仍显示领先和差距 | 已修 |
| 中 | RCV 首轮和决选前的领先被计入 | 已修：不显示领先 |
| 中 | 票数变 null 被算成更正；总数基准不一致 | 已修 |
| 中 | 多席比赛只含部分席位，胜者多于席位 | 已修 |
| 中 | 覆盖分母 42、76 | 已修 |
| 中 | 进度条把各党堆叠后越过多数线；参议院只有 35 席改选，多数线在没有留任席位时够不到 | **未修**，见下 |
| 低 | 失败来源计入覆盖；证据写 `TBC` 也能过；缺 `Returned` 被当重计；空票数被加成 0；2CP 百分比把未知当 0 | 已修 |
| 低 | 回放时失败的来源显示 fresh；继承比赛的 `snapshotId` 被覆盖；已认证加 `source_error` 的文字不一致 | 未修，暂无实际路径 |

M5 时我把「VEC 撤销」时的权威方和时间丢掉了，也是收紧校验时才发现的，已修。

### 接美国来源前必须先做

1. 同一席位的特别选举加常规选举，以及日期晚于投票日的决选（如佐治亚）。现在会被拒绝，采集器保留旧值，不会发布错误数据。
2. 参议院留任席位和党团来源。没有它们，进度条和 51 席标记不能表达控制权。
3. 进度条改成两党从两端向中间。

这三项今天都没有实际路径：美国没有接任何来源。

### 与工作包 schema 的差异（有意）

- `seatIds` 是数组：一个维州大区一次选 5 席。
- `counting.method` 增加 `preferential`、`stv`；`progress.unit` 增加 `polling_places`。
- 判定时间可以是 `firstObservedAt`：VEC 不给宣布日期，只记录首次看到的时间，页面上也这么写。
- 没有单独的「空快照」文件：生产页面没有数据时，目录里每个席位本身就显示 `No result loaded`，并有 e2e 守着。

# M9：美国 2026 接入 civicAPI

日期：2026-11-07。站主决定：直接使用 civicAPI（<https://civicapi.org/api-documentation>），不再先写信询问缓存和转载。

## 做法

**访问者的浏览器直接读 civicAPI，本站不存、不转发。** 这是 M1 §3 提出的替代方案（「改由浏览器直连，不经我们转发」）。civicAPI 的响应头是 `access-control-allow-origin: *`，所以浏览器可以直接读。好处：

- 不需要选运行环境和存储，也没有采集任务。
- 本站从不持有一份 civicAPI 数据，条款里没说的缓存和再分发问题不出现。采集器对它直接拒绝（`browserDirect`）。
- civicAPI 的条款允许免费商用、要求署名。页面在来源面板链接 civicAPI，页脚写明「非正式计票和判定来自 civicAPI（civicapi.org）」。

只在打开「美国 2026」时读取：众议院 `race/87524`、参议院 `race/87528`。页面在前台时每 60 秒读一次，在后台时每 5 分钟一次，失败后退避，沿用 `electionFeed.js`。请求不带 cookie，也不带 referrer。枢纽页和其它选举不读 civicAPI，e2e 有测试守着。

`src/lib/civicApi.js` 把每次读取转成共用契约里的快照。所以校验、发布闸门、过时标记、变化事件都和其它来源一样。

| 字段 | 来源 | 处理 |
|---|---|---|
| 席位 | `region_results` 的键 | 众议院 `ca-01` → `CA-01`；参议院按州对应本届唯一一场（FL、OH 是特别选举，任期到 2029-01-03）。目录里没有的就丢掉 |
| 党派 | `party` | 以 Democrat 开头 → 民主党；以 Republican 开头 → 共和党；其余 → 其他。原文照样显示 |
| 判定 | `winner: true` | `provider_called`，判定方写 civicAPI，依据链接到该 race 的 API 地址。**civicAPI 不给判定时间**，页面写「来源未公布判定时间；本页首次读到的时间」 |
| 计票 | 票数 | 阿拉斯加、缅因按排序复选，不显示领先；有人 `advanced` 但无胜者时按决选处理 |
| 进度 | `percent_reporting` | 取整，标「来源估计」 |
| 时间 | `last_updated` | 只有整场的时间，显示在来源面板。每个选区的来源时间都是「—」 |

不合规的单场比赛单独扣下（例如一个席位两个胜者），其余照常显示。整份文件不对（`test_data`、选举类型、投票日不符）就整份拒绝，页面保留上次的有效数据。

## 2026-11-07 用真实数据试跑（本机，不入库）

470 场全部通过校验，0 场扣下。civicAPI 判定：众议院 D 249、R 157；参议院改选的 35 席里 D 20、R 13。还有 30 场无判定，1 场决选（佐治亚）。来源时间是 2026-11-06 13:13 UTC。

## 已知风险（站主已知悉并接受）

- **判定的含义 civicAPI 没写**，也没有判定时间和证据链。M1 看到过 `in-03` 的胜者不是票数最高的人。页面只说「civicAPI 判定」，不说是官方结果。
- **票数会下降**（M1：4 分钟里 33 次）。页面把它记成「更正」，不当作新一批票。
- **只有北卡做过一次对账。** 其它州没有核对过。
- **参议院不改选的 65 席，以及党团归属**，仍然没有来源（M16）。统计条只计改选的 35 席，不画 51 席线，页面不宣布控制权。
- 没有回放：两次读取之间什么都不记录。

## 回滚

`src/config/electionSources.js` 里把 civicapi 的 `enabled` 改回 `false` 并部署，美国页面就回到无结果的预览。


## 4. 实现与设计稿的对应

| 要求 | 实现 |
|---|---|
| 单一状态 | `{event, office, raceId, geographyView, displayMode, snapshotId}`，见 `src/lib/electionState.js`。URL 值逐项校验，非法值被纠正。`?mode=live` 不起作用，有测试 |
| 规则包 | `src/lib/electionRules.js`：席位、多数线、几何类型、时区标签、状态词汇、党色、官方链接 |
| 唯一 office 开关 | 只有标题右侧一组。切换 office 时清空已选 race |
| 枢纽（方案 B） | 时间轨（等距，非时间比例）+ 下一场大卡 + 其余四场卡片。「下一场」由时钟算出，维州关门后自动换成新州 |
| 控制台（方案 A） | 状态带、标题、事件切换、office 开关、统计条含多数线、席位 43% / 席位块 57%、滑出抽屉、可排序比赛表、来源面板、禁用的回放 |
| 手机列表优先 | 统计条 → 席位图 → 比赛表 → 折叠的席位块 → 来源。详情是底部抽屉 |
| 美澳差异 | 党色方向相反；表格列不同（US：Leader / Margin / % reporting；AU：Primary leader / TCP / Swing）；状态词不同（Certified vs Declared by VEC）。状态词在来源面板可展开查看 |
| 双语 | 静态文案 `data-en/zh`，动态文案 `T(en, zh)` 并监听 `afflatus-lang` |

## 5. 没有做到或需要留意的

- **没有服务端预渲染。** 枢纽内容由 JS 生成，构建版的启动脚本会在首次绘制后才加载。没有 JS 时只看到标题和一句说明。
- **公开文案里有内部阶段代号**（如 `M1`、`M4`）。沿用了评审稿的写法，便于现阶段检查。正式上线前应改成读者能懂的话。
- **规则包的常量未经 M1 核验。** 2026 年参议院的 35 州名单（33 个 Class II + FL、OH 特别选举）和各州众议院席位数来自公开制度知识，测试只保证总数，不保证来源。
- **澳洲选区是占位。** `Seat 01` 等，抽屉里有说明。
- **Lighthouse 基线需要在 M3 后重测。** 席位图会改变字节数。
- **M0 的门禁表漏了一项：** `tests/lighthouseConfig.test.js` 要求每个 active 路由在 `lighthouse-baseline.json` 里有实测数据。已补上。
- **`site:generate` 要跑两遍才稳定：** 第一遍在写页头之前算 sitemap 日期。改页头后再跑一次 `node scripts/site-manifest.mjs --write`，否则 `site:check` 报漂移。这是既有脚本的顺序问题，没有修改。
- **所有页面的 sitemap 日期变成今天。** 页头加了一项，所有 HTML 都算改动，这是工具的既定行为。
- **Playwright 配置里的 `reducedMotion` 实际没有生效。** 它写在 `use` 顶层而不是 `contextOptions` 下，所以 e2e 跑的是有动画的页面。不影响本页结果，spec 已等动画结束，配置没有改。

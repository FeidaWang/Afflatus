一条面向有 AI 编程经验、具备初中级 IT 基础、没有计算机相关本科学位的实践路线。学习目标不是生成更多代码，而是把真实问题变成可以理解、验证、部署、维护和持续使用的工具。

资料核对基线：2026 年 9 月 27 日｜版本：公开分享版 1.0｜形式：自学课程与项目实验，不是大学学位、职业认证或就业承诺。

本文的周数、阅读时间、实验规模和过关标准均为课程设计建议；研究结果与平台规则在对应位置给出原始来源。链接到课程不等于获得其全部实验、证书或付费内容的访问权。公开资料的核对范围见文末资源表，实施时仍需检查当前版本。

导读：为什么不是另一份“AI 课程大全”

很多人已经能够用自然语言做出网页、脚本甚至完整应用，却仍然面对同一组问题：代码出错后只能让模型重写；工具在演示中很好用，进入生活却增加维护；资料收藏了很多，但下一次遇到同类问题仍然不知道如何判断；模型不断更新，项目却也随之不断推倒重来。

这里要补的不是更多提示词，而是一条完整的能力链：

发现一个重复问题 → 选择最简单的解决办法 → 理解核心实现 → 检查结果 → 在合适环境运行 → 接管故障 → 证明它值得保留。

本文借鉴 FDE（Forward Deployed Engineer，前线部署工程师）式的端到端工作方式，但把第一个使用者设为自己。“个人 FDE”是本课程对学习路径的命名，不是行业统一认证名称。课程中的 RSI 按 Recursive Self-Improvement 理解，主线仅指对提示、工具、工作流和代码进行受控改进，不声称实现基础模型权重自训练或无限智能增长。

三个问题贯穿全程：我能解释吗？我能验证和恢复吗？它真的改变了我的日常吗？

一、怎样使用这份路线

1. 适合谁，以及不适合怎样使用

适合已经尝试过 AI 编程、会使用电脑和常见 IT 工具，但软件基础并不系统的人。完全初学者可以先做下文桥接，再进入主线；有经验的工程师可以直接做诊断与验收，补真正的缺口。

不要把它当成必须连续二十四周不间断完成的挑战，也不要把大学公开课全部堆成前置条件。每周只有一个主问题、一个可见交付和一项独立练习。完成标准是能力，而不是日历翻页。这里没有“必须先花钱购买某一款模型”的入学门槛。

已有项目的人优先改进自己的低风险项目；没有项目的人沿用本文三个通用案例。不要同时积极开发三个系统，每次只推进当前主项目，其余只做实际使用与必要维护。

2. 时间预算：每周十小时核心，两小时机动

环节 核心预算 应留下什么
选读官方课程与文档 2 小时 当前问题的理解与一两个疑问，不是所有视频观看记录
构建和验证 5 小时 一个有用的最小改动与实际检查结果
不用代码生成器的小练习 1 小时 自己解释、修改或修复一个问题
在真实低风险任务中使用 1 小时 使用情况与摩擦，不只是演示截图
复盘、维护与资料更新 1 小时 继续、简化、暂停或删除的决定

每周可再留两小时补基础。按每周 10–12 小时估算，24 周的计划投入为 240–288 小时；每周只有 6 小时，可以把同样工作量摊到约 40–48 周，基础差距和任务复杂度仍可能继续延长。

每周资源表的分钟数是建议阅读预算，不是整门课的官方时长。表中“选读”“复习”“补基础”不是额外全修要求；超出两小时后，优先读当前任务卡住的内容，剩余放进机动时间。读完不等于掌握，没读完也不必阻止一个已被理解的小交付。

3. 先做诊断，不先买一整套课程

用 60–90 分钟完成以下检查。可以查官方文档，但先保留自己的首次答案，不让 AI 代答。

检查点 合格表现 暂时不会时补什么
小函数与数据 能解释输入输出，预测一组新数据的结果 R12 · CS50P Week 0：Functions, Variables 或 R27 · MDN：JavaScript Guide 的函数、变量、集合
错误与测试 能读错误位置，写一个反例与期望结果 R03 · MIT Missing Semester：Debugging and Profiling、R13 · CS50P Week 5：Unit Tests
文件与运行环境 能说明当前目录、读写位置、怎样启动 R02 · MIT Missing Semester：Course Overview and the Shell、R14 · CS50P Week 6：File I/O
Git 与安全修改 能看差异、保存可用版本、撤销一个改动 R04 · MIT Missing Semester：Version Control (Git)、R31 · Pro Git：在线书籍
Web 数据流 能区分浏览器、服务器与外部 API R26 · MDN：Core learning modules、R32 · MDN：Overview of HTTP
数据与秘密 能区分零与未知，知道凭据不该放前端或公开仓库 R17 · Harvard CS50 SQL、R59 · OWASP：Secrets Management Cheat Sheet

大量缺项时，加一段约 4–8 周的桥接：第一段练函数、分支、循环和数据；第二段练文件、错误与测试；第三段练 Git、环境与 Web 数据流；第四段用一个本地工具串起来。时间只是安排，仍不会时继续补。算法、内存和数据结构可以从 R16 · Harvard CS50x 2026 按缺口选学，不需要先把全部本科课程修完。

4. 一条主技术栈，不同时学五个框架

默认主线选择 JavaScript / TypeScript → React → Node → SQL → Git。已有稳定技术栈的人可以保留，不必为了这篇文章重写。Python 只用于补基础、阅读研究和小实验；前六周不要同时建设两套完整后端。

R28 · TypeScript Handbook：Introduction、R29 · React：Quick Start 与 R30 · Node.js：Learn 是语言和运行时查阅入口。R21 · Full Stack Open：About the course 列出了 Full Stack Open 的先修期待，因此先补基本编程与 Web，再选其中相关部分。向量数据库、Kubernetes、微调、多 agent 集群和复杂消息系统都不是开工前置条件。

实现顺序保持克制：规则能解决就用规则；需要语言理解才引入模型；步骤固定就用工作流；只有需要受约束地选择行动时才增加 agent 自主性。简单优先的工程思路可参考 R41 · Anthropic：Building effective agents。

二、2026 年应吸收什么，又不应该追什么

MIT Missing Semester 已有 2026 课程，其中包含 Agentic Coding；它适合补齐终端、Git、调试与交付这类容易被跳过的能力。Stanford CS146S 当前主页为 Fall 2026，涉及 MCP、skills、规格与人机协作循环，但明确要求相当于 CS111/CS161 的编程经验；不能把它说成零基础课，也不能据课程介绍假定未来全部材料已经开放。资料见 R01 · MIT Missing Semester：2026 课程目录、R06 · MIT Missing Semester：Agentic Coding、R09 · Stanford CS146S：The Modern Software Developer，Fall 2026。

当前工程材料值得学习的，不仅是提示词，还包括执行环境、仓库信息、反馈与结果检查。本文从 R47 · OpenAI：Harness engineering、R42 · Anthropic：Demystifying evals for AI agents 等原始文章中选取相关思路，再设计自己的练习；没有复制厂商内部成绩，也不保证同样收益能够在个人项目复现。

AI 辅助完成任务与学习者掌握技能是两个不同目标。一项受控编程学习研究提示，使用方式与理解形成有关，但它的样本、任务和实验条件有限，不能推广为“AI 一定损害学习”。本课程因此保留独立解释和新情景练习，而不是禁止使用 AI。研究来源见 R45 · Anthropic：How AI assistance impacts the formation of coding skills。

选课只保留少量主线：基础用 MIT、MDN 与 CS50 的对应章节；Web 交付用 Full Stack Open 与官方文档；agent 基础用 Hugging Face 加一个主 SDK；后期再选 Berkeley 2025 的进阶材料、GEPA 和 DGM。厂商培训在 R38 · OpenAI Academy：Codex 与 R39 · Claude Academy：Claude Code in Action 中选择自己实际使用的一条即可，不需要两套从头重复。

“前沿”应表现为能及时核对变化、做小范围验证和删除过时机制，而不是永远重建技术栈。

三、三个持续项目，以及它们的数据边界

项目 要解决的问题 第一版边界 主要训练阶段
P1 本地周计划工具 重复录入、时间冲突与计划导出 本地处理，手动导出；时段与规则由用户配置，不写入私人云日历 第 1–8 周
P2 知识行动工作台 资料难追溯、读完没有行动 少量公开来源，先只读，输出证据与行动卡 第 9–18 周
P3 AI 任务与成本账本 模型选择凭印象、用量与返工不清楚 只记录授权可得的最小元数据，不收集完整私人对话 第 19–24 周

公开教程中的名字、数据和任务均为通用教学设计，不对应具体个人、雇主、客户或真实项目。不要把自己的真实记录直接替换进公开示例后再次发布。

推荐的架构由风险推动，而不是由框架流行度推动：

P1：用户输入 → 本地规则与校验 → 预览 → 用户主动导出

P2：固定公开来源 → 只读检索 → 必要时调用模型
                         ↓
              证据校验 → 行动草稿 → 人工决定
                         ↓
                    最小运行记录

P3：授权可得的任务元数据 → 本地统计 → 改进提案
                                      ↓
                         隔离评测 → 人工批准或拒绝

这是一张课程架构示意，不代表已经部署的服务。所有跨网络边界都要重新判断数据、权限与费用；模型提出动作，不等于已经获得执行许可。

四、学习时怎样使用 coding agent

采用一个固定循环：先自己预测 → 协作实现 → 解释数据流 → 独立小改动 → 新情景验证。

不要让模型一次读完全部二十四周并开始连续执行。当前周只给目标、必要文件、输入输出、非目标和安全边界；让它先检查真实项目状态，再提出最小计划。每轮结束保留实际验证、未验证项和下一步，不要求它为每个细节制造长报告。

导师、开发者与复核者可以是同一个模型在不同阶段扮演的角色，也可以用两个工具分工。第二个模型的同意只是额外线索，不能替代代码执行、原文证据和人对外部结果的确认。独立练习期间，模型可提问但不提前显示完整答案。

下面的提示词可以作为每周提示的共同前提：

你是我的工程导师和协作开发者。先确认本周目标与当前项目状态，
只处理一个小而完整的任务，不自动推进下一周。

我需要理解输入、处理、输出、失败、权限、费用和恢复方法。
先给最小规格与非目标，再实现最少改动，并实际执行相关检查。
结果分成：已交付、已验证、未验证、风险或限制、我的独立练习。

默认使用合成或公开数据，默认 mock、只读、手动触发。
未经明确授权，不联网发送私人数据、不启用付费调用、
不连接账号、不公开发布、不扩大权限、不删除或覆盖源数据。

不把配置文件或提示词中的限制说成已经落实的安全控制。
不编造测试结果、运行历史、用量或用户反馈。
遇到基础缺口先缩小任务、解释并出小练习，不用大规模重写掩盖它。

这段提示词只是沟通约定，不是安全边界本身。真正的文件、网络、预算和动作限制必须由系统权限与执行程序落实。外部课程的正式作业另外遵守其学术诚信要求，例如 R15 · CS50P：Academic Honesty；本文鼓励 AI 协作的自有项目不应成为规避课程规则的理由。

五、24 周全景图

周次 主问题与章节 阶段成果
01 从生活摩擦出发：诊断基础，做出第一个本地工具 一页问题说明
02 把“能运行”变成“输入可信”：函数、数据结构与校验 数据约定
03 学会接管故障：Git、依赖、调试与最小修复 可复现运行说明
04 让记录可信：SQL、关系、约束与迁移 schema 与迁移
05 把程序变成可用页面：Web、HTTP 与 API 边界 可交互最小页面
06 第一次真正交付：构建、发布包与可用的回滚 可使用的发布产物
07 像 FDE 一样发现问题：先理解流程，再决定功能 一页工作流说明
08 让第一个项目成为习惯：本地计划、日历导出与可用性 P1 可用版本
09 从一次模型调用到最小 agent：先明确何时不需要自主性 最小只读循环
10 为 agent 建立评测：让“完成了”有外部证据 初版评测集
11 上下文、skills 与 MCP：把能力接进来，也把权限挡住 上下文与交接卡
12 知识工作台第一步：从来源到可追溯的证据 最小来源库
13 把知识变成行动：提出预测，做一个能失败的小实验 一张行动卡
14 检验真正掌握：复测、迁移与知识库减负 一份独立复测
15 部署只读运行时：明确运行位置、认证和每一笔费用 可运行只读版本
16 让运行能够恢复：持久状态、重试、幂等与备份 持久状态与去重
17 连接一个真实工作流：先生成草稿，再按范围审批 单连接器说明
18 从演示走向运维：运行观察、告警与事件处理 真实运行报告
19 建立可信经验：AI 任务账本、用量估计与不确定性 可信任务账本
20 受控 RSI：让一次改进有假设、有预算，也可以被拒绝 一份改进提案
21 代码层改进：补丁、隔离评测与人为控制的发布 可审查补丁
22 第二位用户：观察任务、得到同意、完成交接 知情同意与观察方案
23 价值审计：计算净省时，也允许删除自己的作品 一份真实价值报告
24 毕业不是终点：新任务、独立修复与可更新的能力体系 端到端新任务

阶段门槛是：第 3 周能理解修改与调试；第 6 周能交付回退；第 8 周工具进入实际使用；第 11 周能约束 agent；第 14 周知识转化为行动；第 18 周能运维恢复；第 21 周能拒绝无证据自改进；第 24 周能独立处理新需求并说明价值。

下面每周均有具体资料、实践、交付、独立练习和隐私安全检查。资源先选必读和当前卡点，不因出现三个链接就额外完整修三门课。

本周要回答： 这项任务需要语言判断，还是只需要一条清楚的程序规则？

进入本周前： 能读懂简单函数、HTTP 请求和结构化数据；不要求会训练神经网络。

学习内容与理解目标

先分清四层：确定性函数、一次模型调用、预定步骤的工作流、可选择下一步工具的 agent。本周只构造最小只读循环：收到问题、选择已授权工具、检查参数、读取合成材料、返回结果并停止。模型可以提出动作，但执行器决定动作是否被允许。

补足 LLM 的工程常识：输入输出受长度和预算约束，生成结果可能不稳定，结构正确不等于事实正确。理解工具调用是结构化请求，不是模型真的拥有任意系统权限。先用固定 mock 输出理解流程，再选择一个官方 SDK；主线不同时实现多个框架。概念阅读见 R41 · Anthropic：Building effective agents 与 R37 · Hugging Face：Introduction to Agents，Unit 1。

实战拆解

  1. 选一个公开资料小任务，例如从三份合成学习记录中找待复习主题。先实现不用模型的基线，说明哪些步骤已经能靠程序准确完成。

  2. 约定一个结构化结果，至少包括答案、证据标识、无法回答原因。用运行时 schema 检查，不接受为了通过校验而捏造必填字段。

  3. 写 mock 模型：分别返回正常工具请求、未知工具、错误参数和停止信号。执行器只能访问允许的资料，工具输入必须再次校验。

  4. 加入总步数、超时和重试边界；触发边界时返回明确的未完成状态。先确认 mock 会按边界停止，再决定是否进行少量真实调用。

  5. 比较模型方案与确定性基线：在哪种语言任务上有额外价值，在哪种任务上只是更慢、更贵或更不可预测。保留不使用 agent 的决定。

交付与验收

本周交付 怎样确认真的完成
最小只读循环 正常路径可执行，未知工具与越界参数被执行器拒绝。
结构化结果 格式检查与证据检查分开；缺证据时允许不回答。
方案选择说明 指出 agent 比普通函数多解决了什么，或明确决定暂不采用。

不用代码生成器的练习： 不使用代码生成器，画出一次工具调用的消息与执行顺序；然后增加一个不被允许的工具名测试，确认不是靠模型自觉拒绝。

隐私与安全检查： 不开放 shell、任意文件读取、自由 URL 抓取和写入权限。预算、停止条件和工具许可必须在执行器实现，写进提示词只是辅助。此阶段使用公开或合成材料，不接真实账号。

落到日常生活： 让原型处理一个真实存在但低风险的信息查找需求，亲自打开证据核对。若传统搜索更省事，就让模型只承担整理而不是整个流程。

过关或补课判断： 能解释工具循环、拒绝未知工具、区分格式与事实后进入评测阶段。无法确定调用成本时继续使用 mock。

本周可复制的协作提示

请先比较确定性函数、单次调用和只读 agent 三种方案。用 mock 构造工具循环，并在执行器落实参数校验、步数上限和停止状态。未经我明确授权，不发起付费调用或连接账号。

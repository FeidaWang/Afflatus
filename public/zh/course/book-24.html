本周要回答： 面对一个没有做过的小需求和一次故障，你能从需求走到恢复，而不只是重复课程示范吗？

进入本周前： 至少一个确定性工具、一个受控 agent 流程和一次有证据的改进试验；未完成部分如实保留。

学习内容与理解目标

毕业标准是端到端能力，不是视频数量或 agent 数量。选择一个此前未实现的小需求，说明范围、输入、权限和成功标准；完成实现、相关验证、实际使用与恢复。另一项要求是在没有代码生成器代做的情况下完成一次小修复，允许查文档。

之后建立可更新课程：稳定部分是需求、数据、网络、验证、权限和维护；变化部分是模型、SDK 与某些控制技巧。新模型可能减少旧机制的必要性，因此更新也应包含删除。概念参考 R46 · Anthropic：Managed Agents 工程文章；不要把任何一次发布公告直接变成全项目迁移命令。

学习链接与选读范围

级别 官方或原始资料 本周只读这些 阅读预算
回顾 R09 · Stanford CS146S：The Modern Software Developer，Fall 2026 用当前课程范围检查 AI 协作开发的能力缺口，勿当作学历等价。 25 分钟

实战拆解

  1. 独立界定一个新需求，先写最小规格和非目标。让 agent 协作实现，但由你审查数据流、权限和关键差异，记录未验证内容。

  2. 执行新任务的核心检查和一次实际使用，随后制造一个可恢复的小故障。亲自停止、定位、恢复，并确认没有遗漏外部动作。

  3. 完成一次无代码生成器的小修复或规则变更，用自己的话解释原因和验证；若做不到，将它写进下一阶段补课计划。

  4. 整理公开作品材料：问题、架构、合成例子、验证方法、已知限制、真实但脱敏的汇总或明确标记的演示数据。没有实际结果就不写成功故事。

  5. 在固定任务上评估一个模型或 SDK 更新提案，预算和权限不变。结论可以是不升级；记录版本、来源、采用条件和回滚。为下月只设一个主学习方向。

交付与验收

本周交付 怎样确认真的完成
端到端新任务 需求、实现、验证、使用与限制能连起来说明。
独立恢复证据 本人能接管故障，而非完全依赖模型重新生成项目。
公开作品与更新规则 不含私人记录，事实与演示分开，后续路线按真实缺口制定。

不用代码生成器的练习： 关闭代码生成器，解释一个关键模块、修复一个新小问题并恢复一个已知故障。遇到不会的地方直接标出，作为后续学习起点。

隐私与安全检查： 公开发布前重新审查所有文件、构建产物、链接、截图、元数据和历史。没有秘密扫描命中不代表已经安全；真实站点的认证、托管日志、分析脚本和权限还要分别核查。原文课程与研究的版权不因被本教程链接而改变。

落到日常生活： 保留两三个真正进入生活的工具，淘汰其他原型。让技术减少日常负担，而不是让所有生活环节都依赖一个复杂自动化系统。

过关或补课判断： 能交付、验证、恢复、解释价值，并知道自己的不足，即完成本路线；这不是大学学位或某个职位的录用保证。

本周可复制的协作提示

请以新需求、独立修复和恢复演练检验我的能力，只使用真实执行证据。整理可公开的合成演示与限制，不写虚构成绩。对模型或 SDK 升级做有预算比较，允许不升级，并按缺口提出一个后续主方向。

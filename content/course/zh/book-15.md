> **本周要回答：** 电脑合上后任务还会运行吗？由哪个账号付费？谁能打开结果？

**进入本周前：** P2 能手动工作，有基本评测与数据边界；理解浏览器和服务器，能恢复代码版本。

### 学习内容与理解目标

部署的是受控运行环境，不是把聊天窗口搬到网页。先区分开发 agent、应用运行 agent 与评测工具：它们可以使用不同模型、账号范围和费用预算。把运行方式分成两个可选路径：本地手动运行的个人工具，或带认证的只读托管服务；两者都是合格学习成果，不要求购买云服务。

本周先不自动调度。定义触发方式、运行身份、存储位置、谁能访问、如何停止，以及订阅、API、托管三笔费用分别如何计量。订阅支持哪些官方自动化由当时文档决定，不应假定任意自建应用都能免费调用模型；计费核对入口见 [R53 · OpenAI：ChatGPT 与 API 的计费管理](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform) 与 [R54 · Codex 使用与计费入口](https://developers.openai.com/codex/pricing/)。

### 实战拆解

1. 画出运行图：用户手动触发，执行器读取固定公开来源，模型生成结果，结果存到受控位置。每个跨网络箭头写出字段、身份和费用归属。

2. 选择路径 A：在自己的设备运行 Node 进程并手动触发，说明睡眠、断网与关机的限制；或路径 B：按官方指南部署单个小服务，使用标准认证组件或托管访问控制，不自创密码协议。

3. 先部署不使用模型的健康检查与 mock 任务。通过另一未登录会话验证未授权请求被拒绝，错误响应不泄露配置；“别人不知道地址”不是验收标准。

4. 把密钥放到当前平台的秘密管理机制，运行前验证认证路径与预算。只有明确授权后才执行一两个真实只读任务，并记录实际费用或未知值。

5. 写下停止方式、凭据撤销方式、产物位置和清理方式。将真实配置与公开示例分开；文档里的默认模式保持 mock。

### 交付与验收

| 本周交付 | 怎样确认真的完成 |
|---|---|
| 可运行只读版本 | 运行位置、触发方式与睡眠/关机行为明确。 |
| 实际访问检查 | 未授权会话不能访问结果或触发任务；不能只检查页面有登录按钮。 |
| 三笔费用说明 | 订阅、API、托管分别列出来源；不知道费用时不自动运行。 |

**不用代码生成器的练习：** 自己追踪一次 mock 请求，从 HTTP 到执行器再到结果；故意移除一项配置，确认系统清楚拒绝而不是默认走真实服务。

**隐私与安全检查：** 生产秘密不进入前端构建、截图、评测附件或日志。消费订阅并不等于机构批准的数据处理环境，代码在本地也不等于模型推理留在本地。托管平台的日志、备份和子处理方应另行核查。

**落到日常生活：** 让自己从一个固定入口完成一次公开资料整理，不再手工打开开发工具才能运行；同时保留手动替代流程，避免服务故障阻断生活。

**过关或补课判断：** 能停止、能说明谁可访问、知道费用归属且未授权访问被实际拒绝，才增加调度。缺少其中一项就保留本地手动。

> **本周要回答：** 能在自己的开发窗口里运行，与别人按说明就能使用，差了哪些步骤？

**进入本周前：** 已有一个小页面或本地工具，知道如何运行测试、检查网络和回退代码。

### 学习内容与理解目标

本周区分开发服务、生产构建和发布版本。学习构建输入、依赖锁定、环境配置、最小相关检查与版本说明；发布不必等于公开上线，本地可运行包也是合格交付。能够交付一个普通工具，是后面部署 agent 的基础。

验证分层即可：核心逻辑用快速单元测试，界面做一条重要流程检查，发布前从干净环境启动。不要把每个 CSS 调整都升级成全站截图矩阵，也不要依赖“agent 说所有测试通过”。保留真实命令、退出结果和必要日志，而不是补写一个想象中的验收报告。

### 实战拆解

1. 选择一种交付：离线页面、本地命令行包，或仅含合成数据的私有测试站。没有实际需要，就不要同时发布三个平台。

2. 写一个新人能照着执行的启动流程，明确版本、依赖、必要配置和离线限制；缺少配置时应清楚报错，不默认连接真实外部服务。

3. 执行与改动范围相关的最小检查，再从新的目录或干净环境打开发布产物。对比开发版与发布版的核心行为，检查有没有测试数据混入。

4. 保存一个已验证的版本和一份简短变更说明；实际回退一次。如果涉及数据结构变化，说明仅回退代码是否足够，必要时还要恢复数据。

5. 做一次发布前内容审查：源文件、压缩包目录、截图、日志、构建文件、隐藏文件与代码历史。只把读者真正需要的文件纳入发布包。

### 交付与验收

| 本周交付 | 怎样确认真的完成 |
|---|---|
| 可使用的发布产物 | 从干净环境按说明运行，真实走完一条核心流程。 |
| 验收记录 | 明确已执行与未执行项目，不能用“应该通过”代替结果。 |
| 恢复路径 | 版本回退经过操作验证，数据迁移风险有说明。 |

**不用代码生成器的练习：** 自己制造一项无害的配置缺失，读错误并恢复；不用让模型重新生成整个项目。

**隐私与安全检查：** 不公开上传 `.env`、真实数据库、日志、聊天记录、浏览器导出或整个工作目录。公开地址不是私有认证；开发服务器也不应不加限制地暴露到外网。发布前排查方法可参考 [R64 · GitHub：Removing sensitive data from a repository](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

**落到日常生活：** 连续使用至少两次，记录你是否仍需要回到开发工具才能完成日常操作。减少对开发环境的依赖，是从玩具转成工具的标志。

**过关或补课判断：** 第三方或未来的自己能照说明运行、出错能停止、版本能恢复，即通过第一阶段。没有做到时先缩小交付范围，不进入复杂 agent 部署。
